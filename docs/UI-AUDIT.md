# Interface Audit

This pass looked for generic dashboard conventions, vague copy, and controls whose behavior was not clear from their labels. The underlying security workflows and the supplied severity/token system were retained.

| Before                                                                          | Change                                                                                                  | Reason                                                                                            |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Four standalone KPI tiles with decorative icons, then four equal-weight numbers | One critical queue with the oldest unresolved finding and three smaller linked measures                 | The first question is which exposure to investigate, not how many assets exist.                   |
| "One clear picture", "keep the momentum", and similar slogans                   | Derived finding totals and task-specific language                                                       | The dashboard now says what needs review and how many targets it affects.                         |
| Unconditional "All systems operational" and a permanent notification dot        | Both removed; the notification indicator appears only for actual open critical findings or failed scans | The demo does not claim a live system health signal it does not have.                             |
| Repeated globe/file icons, four boxed severity numbers, arrow on every row      | Plain asset names, legible nonzero counts, and keyboard-operable rows                                   | Removed ornament without hiding useful evidence.                                                  |
| Acme fixture names and live-looking hostnames                                   | A coherent fictitious Westhaven workspace using reserved `.example` domains                             | The sample data reads as one system and cannot be mistaken for an authorized scan of a real site. |
| Decorative double-icon empty illustration                                       | A single quiet icon with a specific action                                                              | The empty state remains identifiable without drawing attention away from the work.                |
| Native browser `title` hints on collapsed navigation                            | Owned shadcn-style Radix tooltip on hover and focus                                                     | Tooltip labels match the rest of the UI, including keyboard use.                                  |
| Rounded pastel severity/status pills and circular loading glyphs                | Severity rails, rectangular status marks, a linear scan bar, and text-only pending buttons              | Status and urgency remain distinct without looking like gamified badges.                          |
| CWE buried under the title and generic category names                           | A dedicated sortable CWE column and official OWASP Top 10 labels                                        | The centrepiece table now matches the data contract.                                              |

The shared `TooltipProvider` lives at the app root. `Tooltip`, `TooltipTrigger`, and `TooltipContent` are locally owned Radix primitives in `src/components/ui/Tooltip.tsx`; `IconHint` composes them with existing buttons and links using `asChild`. Compact navigation tooltips are active for manual collapse and the 681-900 px breakpoint. The expanded sidebar and open mobile drawer keep visible labels and do not duplicate them with tooltips. Header actions, row editing/deletion, copying evidence, clear controls, and dialog dismissal use the same hint pattern.

Sign-out stays accessible even when the navigation is icon-only. Hover, keyboard focus, route activation, mobile overflow, and WCAG 2.1 AA checks are covered by automated tests and the Chromium smoke run. Settings includes a disabled, clearly labeled API-key placeholder; Reports includes an explicitly labeled PDF placeholder alongside real HTML/JSON/CSV exports. The mock scans and first-report failure are intentional assessment scenarios, not live security assertions.
